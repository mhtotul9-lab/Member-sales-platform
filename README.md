# Member Sales Platform — সম্পূর্ণ (Phase 0 থেকে Phase 6) + বাগ ফিক্স আপডেট

## ⚠️ আপনি যেহেতু আগে একবার ডিপ্লয় করেছেন — এই আপডেটটা কীভাবে বসাবেন

এই ভার্সনে ৩টা জিনিস ঠিক করা হয়েছে যেগুলো আপনার আগের ডিপ্লয়মেন্টে সমস্যা করছিল:

1. **সব ফিচার নেভিগেশনে যোগ করা** — আপনার আগের ডিপ্লয়মেন্টে Nav-এ শুধু মেম্বার/প্রোডাক্ট/অর্ডার/প্রফিট ছিল, কারণ ওটা পুরনো (Phase 4) কোড ছিল। এই zip-এ উইথড্র, ট্রেনিং, লিডারবোর্ড, অডিট লগ, রিপোর্ট, সেটিংস — সব লিংক আছে।
2. **API এরর হ্যান্ডলিং** — আগে কোনো এরর হলে (যেমন Firestore index মিসিং) পুরো পেজ ক্র্যাশ করে HTML এরর পেজ দেখাত, যেটা ফ্রন্টএন্ড JSON হিসেবে পড়তে না পেরে "Unexpected token '<'..." এরর দিত। এখন সব এরর সুন্দর বাংলা মেসেজ আকারে দেখাবে।
3. **সব Firestore index একসাথে ডিপ্লয়** — নিচে দেখুন।
4. **মোবাইল রেসপন্সিভ মেনু + লোগো/ফেভিকন** — ছোট স্ক্রিনে এখন হ্যামবার্গার (☰) মেনু দেখাবে, আর ব্রাউজার ট্যাবে/নেভবারে একটা কাস্টম লোগো দেখাবে।

**যা করতে হবে**: আপনার GitHub রিপোর সব ফাইল মুছে এই নতুন zip-এর সব ফাইল দিয়ে replace করুন (অথবা রিপো ক্লোন করে পুরনো ফাইলের উপর নতুন zip এক্সট্র্যাক্ট করে overwrite করুন), তারপর:

```bash
git add -A
git commit -m "Bug fixes: error handling, indexes, mobile nav, logo"
git push
```

Vercel automatically নতুন ডিপ্লয়মেন্ট শুরু করবে। **তবে তার আগে নিচের ইনডেক্স ডিপ্লয়মেন্ট ধাপটা করে নিন**, নাহলে আগের এররগুলো আবার দেখবেন।

## Firestore Index — একসাথে সব ডিপ্লয় করুন (এক-বারের কাজ)

আগে বলেছিলাম এরর মেসেজের লিংকে ক্লিক করে একটা একটা করে ইনডেক্স বানাতে — কিন্তু সেটা ধীর এবং প্রতিটা ফিচার একবার ব্যবহার না করা পর্যন্ত এরর দেখাই যায় না। এখন `firestore.indexes.json` ফাইলে সবগুলো ইনডেক্স একসাথে লেখা আছে, একটা কমান্ডেই সব বসিয়ে দিতে পারবেন।

আপনার কম্পিউটারে (যেখানে প্রজেক্ট ফোল্ডার আছে) এই কমান্ডগুলো একবার চালান:

```bash
npm install -g firebase-tools
firebase login
```

`firebase login` চালালে ব্রাউজার খুলবে, আপনার Google অ্যাকাউন্ট (যেটা দিয়ে Firebase প্রজেক্ট বানিয়েছেন) দিয়ে লগইন করুন।

তারপর প্রজেক্ট ফোল্ডারের ভেতরে গিয়ে:

```bash
firebase deploy --only firestore:indexes --project jolrasi-member-sel
```

এটা `firestore.indexes.json` ফাইলে থাকা সবগুলো ইনডেক্স একসাথে Firebase-এ পাঠিয়ে দেবে। Firebase Console-এর **Firestore Database → Indexes** ট্যাবে গিয়ে দেখতে পারবেন — কিছুক্ষণ (৫-১৫ মিনিট) "Building" স্ট্যাটাসে থাকবে, তারপর "Enabled" হয়ে যাবে। সব ইনডেক্স Enabled হওয়ার পর অ্যাপ ব্যবহার করুন।

**বিকল্প (যদি CLI ব্যবহার করতে না চান)**: আগের মতোই, কোনো ফিচার ব্যবহার করার সময় যদি এরর মেসেজে ইনডেক্স তৈরির কথা বলে, Vercel Dashboard → আপনার প্রজেক্ট → **Observability** (বা **Logs**) ট্যাবে গিয়ে সেই মুহূর্তের Function লগ খুঁজুন — সেখানে সম্পূর্ণ এরর মেসেজে একটা লিংক থাকবে, ওখানে ক্লিক করলেই নির্দিষ্ট ইনডেক্সটা তৈরি হয়ে যাবে। কিন্তু CLI দিয়ে একসাথে করে ফেলা অনেক দ্রুত।

এই ভার্সনে আছে:
- প্রজেক্ট স্ট্রাকচার, Firebase সেটআপ, রেজিস্ট্রেশন → অ্যাডমিন অ্যাপ্রুভাল → লগইন
- প্রোডাক্ট ম্যানেজমেন্ট + মার্কেটিং কিট (external image/video URL + কপি-করা-যায় ক্যাপশন)
- মেম্বার প্রোডাক্ট ব্রাউজিং (সার্চ, ক্যাটাগরি ফিল্টার)
- অর্ডার সাবমিশন + অ্যাডমিন ভেরিফিকেশন + ডুপ্লিকেট/ফ্রড ফ্ল্যাগ + টাইমলাইন
- Active/Inactive সিস্টেম (রোলিং উইন্ডো, সেটিংস থেকে কনফিগারযোগ্য) + Profit Pool + Wallet Ledger
- উইথড্র সিস্টেম (রিজার্ভেশন + অ্যাপ্রুভ/পেইড/রিজেক্ট ফ্লো)
- লিডারবোর্ড (সাপ্তাহিক/মাসিক/অল-টাইম)
- নোটিফিকেশন সিস্টেম (পোলিং-ভিত্তিক আনরিড কাউন্ট)
- **ট্রেনিং মডিউল**: অ্যাডমিন ট্রেনিং তৈরি করে (টেক্সট + ভিডিও/PDF লিংক), মেম্বার দেখে ও "সম্পন্ন করলাম" মার্ক করে, অ্যাডমিন প্রতিটা ট্রেনিং কতজন সম্পন্ন করেছে দেখতে পারে
- **রিপোর্ট (CSV এক্সপোর্ট)**: `/admin/reports` থেকে অর্ডার/মেম্বার/উইথড্র রিপোর্ট CSV হিসেবে ডাউনলোড করা যায় (Excel/Google Sheets-এ খোলা যাবে)
- **অডিট লগ ভিউয়ার**: `/admin/audit-logs` এ সব sensitive অ্যাকশনের (স্ট্যাটাস পরিবর্তন, সেটিংস আপডেট) হিস্ট্রি, এনটিটি অনুযায়ী ফিল্টার করা যায়
- **সেটিংস প্যানেল** (`/admin/settings`): Active window (দিন), Active হতে প্রয়োজনীয় ন্যূনতম সেল সংখ্যা, সর্বনিম্ন উইথড্র পরিমাণ, উইথড্র পেমেন্ট মেথড — এই মানগুলো বদলালে সাথে সাথেই পুরো সিস্টেমে (Active/Inactive হিসাব, প্রফিট স্ন্যাপশট, উইথড্র ভ্যালিডেশন) প্রভাব পড়ে, এটা শুধু UI দেখানোর জন্য নয়

## ইচ্ছাকৃতভাবে যা এখনো বানানো হয়নি

**Multi-role Admin Permission System** (Super Admin / Sales Manager / Finance Admin / Content Manager / Support Admin — স্পেকের সেকশন ৩২): এটা ইচ্ছাকৃতভাবে বাদ দেওয়া হয়েছে। কারণ, একটা রোল-সিলেক্ট UI বানিয়ে দেওয়া সহজ, কিন্তু আসল নিরাপত্তা তখনই হয় যখন প্রতিটা API route নির্দিষ্ট পারমিশন চেক করে ("এই অ্যাডমিন কি প্রোডাক্ট এডিট করতে পারবে? প্রফিট দেখতে পারবে?")। সেটা ছাড়া একটা রোল-ড্রপডাউন শুধু দেখতে কাজ করে বলে মনে হবে কিন্তু আসলে কিছুই রেস্ট্রিক্ট করবে না — এই স্পেকেই বলা আছে "কোন feature শুধু UI-তে দেখিয়ে fake functionality দেওয়া যাবে না।" তাই এখন সিস্টেমে একটাই অ্যাডমিন লেভেল আছে (custom claim `admin: true`) — যে কেউ অ্যাডমিন, সে সবকিছু করতে পারে। ভবিষ্যতে সত্যিকারের সাব-রোল দরকার হলে জানাবেন, তখন প্রতিটা route-এ পারমিশন চেক যোগ করে ঠিকভাবে বানিয়ে দেব।

## গুরুত্বপূর্ণ ডিজাইন নোট

- মেম্বারের দুইটা আলাদা "স্ট্যাটাস" আছে, গুলিয়ে ফেলবেন না:
  - `status` (`members` কালেকশনে) = **অ্যাকাউন্ট অ্যাপ্রুভাল** স্ট্যাটাস — pending/active/rejected/suspended
  - `activityStatus` = **সেলস অ্যাক্টিভিটি** স্ট্যাটাস — active/inactive, রোলিং ৭ দিনের সেল-ভিত্তিক নিয়ম। এটা মেম্বার ওয়ালেট পেজ (`/member/wallet`) খুললে রিফ্রেশ হয়।
- প্রফিট-ভাগের eligible-member লিস্ট আমাদের বাজেট-বান্ধব আর্কিটেকচারে (কোনো Cloud Function/cron ছাড়া) প্রতিটা approval-এর সময় সরাসরি হিসাব করে বের করা হয় — মেম্বার সংখ্যা কয়েকশো পর্যন্ত এভাবে ঠিকঠাক চলবে। ভবিষ্যতে মেম্বার সংখ্যা অনেক বেড়ে গেলে (হাজার+) এটাকে queue/Cloud Function ভিত্তিক করা ভালো হবে — এখন তার দরকার নেই।
- উইথড্র রিকোয়েস্ট করার সাথে সাথেই সেই টাকাটা ব্যালেন্স থেকে "রিজার্ভ" হয়ে যায় (বিয়োগ হয়ে যায়) — যাতে একই টাকা দুইবার উইথড্র রিকোয়েস্ট করা না যায়। Reject হলে টাকা স্বয়ংক্রিয়ভাবে ফেরত আসে।
- নোটিফিকেশন বেল রিয়েল-টাইম নয় — প্রতি ৩০ সেকেন্ডে একবার আনরিড কাউন্ট চেক করে (polling)। ছোট থেকে মাঝারি স্কেলে এটা যথেষ্ট এবং কোনো এক্সট্রা খরচ ছাড়াই কাজ করে।

## ১) Firebase প্রজেক্ট তৈরি

1. https://console.firebase.google.com এ যান → **Add project** → নাম দিন (যেমন `sales-partner`) → তৈরি করুন।
2. বাম মেনু থেকে **Build → Authentication** → **Get started** → **Sign-in method** ট্যাবে যান → **Email/Password** enable করুন।
3. বাম মেনু থেকে **Build → Firestore Database** → **Create database** → **Production mode** সিলেক্ট করে আপনার কাছের region (যেমন `asia-south1`) বেছে নিন।
4. **Project settings** (গিয়ার আইকন) → **General** ট্যাবের নিচে **Your apps** → `</>` (Web) আইকনে ক্লিক করে একটা Web App যোগ করুন। এখানে যে `firebaseConfig` অবজেক্ট দেখাবে, সেটার মান দিয়ে `.env.local` এর `NEXT_PUBLIC_FIREBASE_*` ভ্যারিয়েবলগুলো পূরণ করবেন।
5. **Project settings → Service accounts** ট্যাবে যান → **Generate new private key** → একটা JSON ফাইল ডাউনলোড হবে। এই ফাইলের `project_id`, `client_email`, আর `private_key` — এই তিনটা মান দিয়ে `.env.local` এর `FIREBASE_ADMIN_*` ভ্যারিয়েবলগুলো পূরণ করবেন (private_key এর ভিতরের `\n` গুলো ঠিক তেমনই রাখবেন, এক লাইনে পুরো স্ট্রিং)।

ব্রাউজারে http://localhost:3000 খুলে `/register` দিয়ে একটা টেস্ট অ্যাকাউন্ট খুলুন।

## ৩) প্রথম অ্যাডমিন তৈরি করা

Firestore Rules-এ সবকিছু ডিফল্টভাবে admin-only, তাই প্রথম অ্যাডমিনকে ম্যানুয়ালি সেট করতে হয়:

```bash
npm run set-admin -- your-email@example.com
```

এই কমান্ড আপনার অ্যাকাউন্টে `admin: true` কাস্টম ক্লেইম আর Firestore-এ `role: admin, status: active` সেট করে দেবে। এরপর ঐ অ্যাকাউন্ট দিয়ে লগ আউট করে আবার লগইন করুন — তাহলে `/admin/dashboard` এ যাবে।

## ৪) Firestore Security Rules আপলোড করা

1. Firebase Console → **Firestore Database → Rules** ট্যাবে যান।
2. এই রিপোর জোর `firestore.rules` ফাইলের পুরো কনটেন্ট কপি করে ওখানে পেস্ট করুন → **Publish**।

1. https://vercel.com এ গিয়ে GitHub দিয়ে লগইন করুন।
2. **Add New → Project** → আপনার `member-sales-platform` রিপো সিলেক্ট করুন → **Import**।
3. **Environment Variables** সেকশনে গিয়ে `.env.local` এর প্রতিটা ভ্যারিয়েবল একই নাম আর মান দিয়ে যোগ করুন (৭টা `NEXT_PUBLIC_FIREBASE_*` + ৩টা `FIREBASE_ADMIN_*`)। `FIREBASE_ADMIN_PRIVATE_KEY` পেস্ট করার সময় পুরো স্ট্রিং (BEGIN/END লাইনসহ) এক লাইনে দিন, Vercel নিজে থেকেই `\n` ঠিকমতো হ্যান্ডেল করবে।
4. **Deploy** ক্লিক করুন। কয়েক মিনিটের মধ্যে একটা লাইভ URL পাবেন (যেমন `member-sales-platform.vercel.app`)।

এরপর থেকে যতবার আপনি `main` ব্র্যাঞ্চে পুশ করবেন, Vercel অটোমেটিক্যালি নতুন ভার্সন ডিপ্লয় করবে।

## খরচ সংক্রান্ত নোট

- Firebase **Spark (Free) plan** ব্যবহার হচ্ছে — কোনো কার্ড লাগবে না। Cloud Functions ব্যবহার করা হয়নি, তার বদলে সব সার্ভার-সাইড লজিক Next.js API Routes হিসেবে লেখা, যেটা Vercel-এর ফ্রি টায়ারে চলে।
- Firestore ফ্রি কোটা: প্রতিদিন ৫০,০০০ read এবং ২০,০০০ write — শুরুর দিকে যথেষ্ট।
- প্রোডাক্ট ইমেজ/ভিডিওর জন্য Firebase Storage ব্যবহার করবেন না (এটা পেইড হয়ে যেতে পারে) — পরের ফেজে external URL (ImgBB / Cloudinary ফ্রি টায়ার / YouTube লিংক) ব্যবহার করা হবে, যেভাবে স্পেকেও বলা আছে।
